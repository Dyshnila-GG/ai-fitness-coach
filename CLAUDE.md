# CLAUDE.md — AI Fitness Coach

## Проект
Мобильное приложение (iOS + Android): персональный AI-тренер — калибровка, цели, база упражнений, готовые и свои тренировки, пошаговый плеер тренировки, оценка, AI-генерация следующей тренировки.
Личное приложение для 2 пользователей, без публикации в магазины и без монетизации.
**Полная спецификация — `SPEC.md`. Это источник правды. Не добавляй функции, которых там нет.**

## Стек
- React Native + Expo, TypeScript (strict), Expo Router — запуск только в Expo Go (без dev build), зависимости только совместимые с Expo Go
- NativeWind, Zustand, TanStack Query, AsyncStorage (офлайн)
- Supabase: Auth (email + пароль), Postgres + RLS, Storage, Edge Functions
- Claude API — только из Edge Function (`supabase/functions/`), модель из `ANTHROPIC_MODEL`
- i18next (ru — основной, en), Jest + RNTL

## Структура
```
app/                 # экраны (Expo Router)
src/components/      # UI-компоненты
src/features/        # onboarding, exercises, workouts, player, feedback, progress, ai
src/lib/             # supabase-клиент, утилиты
src/logic/           # чистая бизнес-логика (прогрессия, разминочные подходы) + тесты
src/i18n/            # переводы
supabase/migrations/ # SQL-миграции
supabase/seed/       # seed упражнений и программ
supabase/functions/  # Edge Functions (AI)
```

## Команды
- `npx expo start` — запуск
- `npm test` — тесты
- `npm run lint` / `npm run typecheck` / `npm run format`
- `npx supabase start` — локальный Supabase (Docker)
- `npx supabase db reset` — миграции + seed локально
(Обнови этот раздел, когда команды появятся/изменятся.)

## Правила работы
1. Работай строго по этапам из `SPEC.md` (раздел 13), по одному.
2. Перед кодом каждого этапа — краткий план, жди подтверждения.
3. Маленькие шаги. После каждого законченного шага: typecheck + lint + тесты → коммит (Conventional Commits, на английском).
4. Конец этапа — отметь `[x]` в «Статус этапов» в `SPEC.md` и дай краткий отчёт.
5. Бизнес-логику (прогрессия, deload, разминка, объём) — только в `src/logic/`, чистыми функциями, с unit-тестами.
6. Секреты — только в `.env` (в `.gitignore`), пример — в `.env.example`. Ключ Claude API никогда не попадает в приложение.
7. Любая таблица — с RLS. Пользователь видит только свои данные.
8. AI-ответы — строгий JSON, валидация zod, упражнения только из базы, fallback на детерминированную прогрессию.
9. Плеер тренировки обязан работать офлайн.
10. Все тексты UI — через i18n, без хардкода строк.
11. Не ставь новые зависимости без необходимости; если ставишь — объясни зачем в одну строку.
12. Если требование в `SPEC.md` неясно или противоречиво — спроси, не додумывай.
13. В конце каждого этапа создавай Pull Request в `main` с кратким описанием: что сделано, что проверено.
